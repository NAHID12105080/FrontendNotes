# Design Patterns Summary
Design patterns are reusable solutions to common software design problems. They provide proven ways to structure code, making it more efficient, easier to understand, and maintain.
## 📦 Creational Design Patterns
**Focus:** How objects are created

| Pattern             | Idea                                                   | Real-World Analogy                              |
|:--------------------|:-------------------------------------------------------|:------------------------------------------------|
| Factory Method      | Create objects without specifying exact class.         | Ordering a pizza: kitchen decides which pizza. |
| Abstract Factory    | Create families of related objects.                    | Choosing a "Victorian" furniture set.           |
| Builder             | Step-by-step construction of complex objects.          | Building a burger at Subway: choose items.      |
| Prototype           | Clone existing objects instead of creating new ones.   | Copy-pasting a document template.               |
| Singleton           | Only one instance of a class, globally accessible.     | Only one president at a time.                   |

---

# 🔥 Structural Design Patterns
 **Focus:** How objects and classes are structured

| Pattern             | Idea                                                   | Real-World Analogy                              |
|:--------------------|:-------------------------------------------------------|:------------------------------------------------|
| Adapter             | Make incompatible interfaces work together.            | Phone charger adapter.                         |
| Bridge              | Separate abstraction from implementation.              | TV Remote and TV separated.                    |
| Composite           | Treat group of objects as a single object.              | Folder containing files and folders.           |
| Decorator           | Add behavior dynamically to objects.                   | Adding toppings to pizza.                      |
| Facade              | Simplify a complex system with a unified interface.     | Restaurant menu hiding kitchen complexity.     |
| Flyweight           | Share common parts to save memory.                     | Text editor reusing font glyphs for letters.    |
| Proxy               | Provide a placeholder to control access.               | Internet proxy server.                         |

---

# 🧠 Behavioral Design Patterns
 **Focus:** How objects interact and communicate

| Pattern                  | Idea                                              | Real-World Analogy                              |
|:-------------------------|:--------------------------------------------------|:------------------------------------------------|
| Chain of Responsibility   | Pass a request along a chain of handlers.         | Call center support escalation.                |
| Command                   | Turn a request into a standalone object.          | TV Remote buttons as commands.                 |
| Interpreter               | Interpret sentences in a language.               | Google Translate.                              |
| Iterator                  | Access elements sequentially without exposing structure. | TV Remote \"Next Channel\" browsing. |
| Mediator                  | Centralize communication between objects.        | Air traffic controller.                        |
| Memento                   | Save and restore object state.                   | Undo/redo feature in Microsoft Word.           |
| Observer                  | Notify multiple objects when state changes.      | YouTube subscription notifications.            |
| State                     | Change behavior when internal state changes.     | Traffic lights switching states.               |
| Strategy                  | Define family of algorithms and switch easily.   | Choosing payment method: Credit Card, PayPal.  |
| Template Method           | Define skeleton of an algorithm, allow overrides.| Cooking recipe with optional variations.       |
| Visitor                   | Separate algorithm from object structure.        | Postman visiting houses delivering mail.       |

---

# 🎯 Factory Method 

## ✨ Basic Idea

Define an interface for creating an object, but let subclasses alter the type of objects that will be created.

---

## 📦 Example (Java)

```java
// Product Interface
interface Animal {
    void speak();
}

// Concrete Products
class Dog implements Animal {
    public void speak() {
        System.out.println("Woof!");
    }
}

class Cat implements Animal {
    public void speak() {
        System.out.println("Meow!");
    }
}

// Creator
abstract class AnimalFactory {
    abstract Animal createAnimal();
}

// Concrete Creators
class DogFactory extends AnimalFactory {
    Animal createAnimal() {
        return new Dog();
    }
}

class CatFactory extends AnimalFactory {
    Animal createAnimal() {
        return new Cat();
    }
}

// Client
public class FactoryDemo {
    public static void main(String[] args) {
        AnimalFactory factory = new DogFactory();
        Animal myDog = factory.createAnimal();
        myDog.speak(); // Woof!
    }
}
```
---

## 🎨 Mini Diagram

```
Client → AnimalFactory → Animal
             ↑
        +---------+
        |         |
   DogFactory   CatFactory
```
---

## 📈 Advantages and Disadvantages

| Advantages                              | Disadvantages                          |
|:----------------------------------------|:--------------------------------------|
| Loose coupling between code and classes | Increases number of classes           |
| Easy to introduce new types             | Might be overkill for simple apps     |
| Supports Open/Closed principle          | Can become complex if many products   |

---

- Why use Factory Method instead of directly using `new`?
- What is the difference between Factory Method and Abstract Factory?

- How does Factory Method relate to Dependency Injection?

# 1. Adapter Pattern

## ✨ Basic Idea

> Make two incompatible interfaces compatible without changing their source code.

----------

## 📄 Small Project: "Old Printer - New Computer"

### 📜 Example (Python)

```python
# Old interface
class OldPrinter:
    def connect_via_lpt(self):
        print("Connected using LPT port")

# New interface expected
class Computer:
    def connect_usb(self, device):
        device.connect()

# Adapter
class PrinterAdapter:
    def __init__(self, old_printer):
        self.old_printer = old_printer

    def connect(self):
        self.old_printer.connect_via_lpt()

# Client
printer = OldPrinter()
adapter = PrinterAdapter(printer)

pc = Computer()
pc.connect_usb(adapter)  # Connected using LPT port

```

### 🎨 Mini Diagram

```
Computer --> PrinterAdapter --> OldPrinter
         (expects USB)    (only supports LPT)
```

### 💬 Interview Questions

-   When do you use Class Adapter vs Object Adapter?
    
-   How is Adapter different from Decorator?
    
-   Can you think of a real-world Adapter you use daily?

# 2. Bridge Pattern

## ✨ Basic Idea

> Decouple abstraction from implementation, so they can vary independently.

----------

## 📄 Small Project: "Remote Control for Different Devices"

### 📜 Example (JavaScript)

```javascript
// Implementation
class Device {
  turnOn() {}
  turnOff() {}
}

class TV extends Device {
  turnOn() { console.log("TV turned ON"); }
  turnOff() { console.log("TV turned OFF"); }
}

class Radio extends Device {
  turnOn() { console.log("Radio turned ON"); }
  turnOff() { console.log("Radio turned OFF"); }
}

// Abstraction
class RemoteControl {
  constructor(device) {
    this.device = device;
  }
  turnOn() {
    this.device.turnOn();
  }
  turnOff() {
    this.device.turnOff();
  }
}

// Client
const tvRemote = new RemoteControl(new TV());
tvRemote.turnOn();  // TV turned ON

const radioRemote = new RemoteControl(new Radio());
radioRemote.turnOn();  // Radio turned ON

```

### 🎨 Mini Diagram

```
RemoteControl  ----->  Device
                         ↑
                   +-----------+
                   |           |
                  TV          Radio

```

### 💬 Interview Questions

-   How is Bridge different from Adapter?
    
-   Why use Bridge instead of simple inheritance?
    
-   Can Bridge be combined with other patterns?

# 3. Strategy Pattern

## ✨ Basic Idea

> Define a family of algorithms and make them interchangeable at runtime.

----------

## 📄 Small Project: "Payment Gateway Switching"

### 📜 Example (Java)

```java
// Strategy Interface
interface PaymentStrategy {
    void pay(int amount);
}

// Concrete Strategies
class CreditCardPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " using Credit Card.");
    }
}

class PayPalPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " using PayPal.");
    }
}

// Context
class ShoppingCart {
    private PaymentStrategy paymentStrategy;

    public void setPaymentStrategy(PaymentStrategy paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    public void checkout(int amount) {
        paymentStrategy.pay(amount);
    }
}

// Client
public class StrategyExample {
    public static void main(String[] args) {
        ShoppingCart cart = new ShoppingCart();

        cart.setPaymentStrategy(new CreditCardPayment());
        cart.checkout(500);

        cart.setPaymentStrategy(new PayPalPayment());
        cart.checkout(200);
    }
}

```

### 🎨 Mini Diagram

```
ShoppingCart → PaymentStrategy
                     ↑
            +----------------+
            |                |
  CreditCardPayment    PayPalPayment

```
### 💬 Interview Questions

-   How is Strategy different from State pattern?
    
-   Why not just use if-else instead of Strategy?
    
-   Can you combine Strategy with Factory Pattern?
